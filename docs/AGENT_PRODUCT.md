# AetherMind — Product Agent Guide

## 1. Product Identity

AetherMind is a:

> **Local-first personal knowledge operating system.**

It should understand the user's accumulated knowledge rather than merely store it.

---

# 2. What AetherMind Is Not

Do not optimize AetherMind into:

* a Notion clone
* an Obsidian clone
* a generic chatbot
* a generic AI wrapper
* a graph demo
* a task-management application
* a feature-collection productivity suite

Existing features may remain, but the product direction must remain coherent.

---

# 3. Core Product Loop

The ideal loop is:

```text
Capture
 ↓
Understand
 ↓
Connect
 ↓
Retrieve
 ↓
Reflect
 ↓
Discover
 ↓
Learn
 ↓
Update knowledge
```

Every major feature should strengthen this loop.

---

# 4. Core User Questions

AetherMind should increasingly answer:

### Retrieval

"What do I know about X?"

### Relationship

"How is X connected to Y?"

### Evolution

"How has my thinking about X changed?"

### Discovery

"What patterns are emerging?"

### Gap detection

"What am I missing?"

### Contradiction

"Where do my notes disagree?"

### Learning

"What should I investigate next?"

### Provenance

"Why does AetherMind believe this?"

---

# 5. Product Differentiation

The graph is not the moat.

AI is not the moat.

Markdown is not the moat.

The potential moat is:

> AetherMind develops an increasingly useful computational representation of the user's personal knowledge over time.

This representation should become:

* richer
* more connected
* more accurate
* more explainable
* more useful

---

# 6. Feature Prioritization

Prioritize features that improve:

### P0

* trust
* security
* data ownership
* reliability

### P1

* knowledge intelligence
* retrieval
* graph reasoning
* temporal reasoning
* contradiction detection
* knowledge-gap detection

### P2

* ingestion
* mobile UX
* onboarding
* accessibility

### P3

* cosmetic customization
* novelty features
* low-value convenience features

---

# 7. Killer Workflow

A strategic target workflow is:

```text
Import existing knowledge
        ↓
Build knowledge representation
        ↓
Identify concepts
        ↓
Identify relationships
        ↓
Identify clusters
        ↓
Identify contradictions
        ↓
Identify gaps
        ↓
Ask natural-language questions
        ↓
Receive evidence-backed answers
        ↓
Explore graph/timeline
```

This should be prioritized over superficial feature expansion.

---

# 8. User Trust

AetherMind stores valuable personal knowledge.

Therefore UX should emphasize:

* transparency
* recoverability
* provenance
* explainability
* control
* privacy
* predictable behavior

AI should never silently destroy or substantially rewrite user knowledge.

---

# 9. Explainability

Where feasible, AI-generated conclusions should expose:

* supporting notes
* supporting sources
* relevant relationships
* confidence/uncertainty
* reasoning context at an appropriate product level

Never fabricate explanations.

---

# 10. Product Anti-Patterns

Avoid:

* feature bloat
* unnecessary settings
* unnecessary configuration
* AI for trivial tasks
* decorative graph complexity
* features that increase complexity without increasing knowledge value
* hidden cloud processing
* destructive automation

---

# 11. Product Decision Test

Before implementing a feature, ask:

1. Does this improve the core knowledge loop?
2. Does it make AetherMind meaningfully more intelligent?
3. Does it improve user trust?
4. Does it improve retrieval or understanding?
5. Does it justify its maintenance cost?

If the answer is mostly "no", deprioritize it.

---

# 12. Long-Term Vision

The strongest version of AetherMind is not:

> "A place where I store my notes."

It is:

> "A private system that understands what I know and helps me understand what I should know next."
